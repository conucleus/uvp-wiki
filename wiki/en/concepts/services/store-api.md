# Store Console, Supplier, and Governance API

The Store APIs are the workbench surfaces used by the nucleus, Store operators, reviewers, and governance admins. They organize Zhixu drafts, supplier profiles, docking sessions, review material, publication workflows, identity requests, and audit trails. Within the nucleus-governed Zhixu itself, the Store API owns platform workflow while the Identity Registry projection resolves subject/account mappings.

## Store Console

Store Console serves the nucleus workbench:

- Zhixu search, catalog, and detail.
- Draft import, compile preview, submit review, request publication.
- Version, runtime, active recommendation, chain publication projection.
- Docking sessions for trial-assembling peer Zhixu, adapters, or signal maps.
- Audit trail recording platform workflow actions.

These states are platform workflow and material organization. Identity bindings are expressed by `UVPIdentityRegistry` events; capability, recommendation, and matching remain off-chain Store judgments.

## Supplier Directory

The Supplier API organizes materials for the real-world fulfillment network:

- Supplier subject, wallet, display name.
- Capability tags, role/stage availability.
- Contact profile, owner, SLA, operational notes.
- Participation history, open tasks, proof links.
- Review, publication request, revocation request.

Store admins can maintain the platform directory and review materials. Participation rules inside a Zhixu are decided by the nucleus; order-level authorization is generated by the Product BFF and checked by the contract.

## Governance Workflow

The Governance API manages platform review, identity binding register/revoke requests, tx intents, and audit. It can organize material and initiate Registry operations; the recorded result is expressed by `UVPIdentityRegistry` events and projections.

For governance process and permission details, see [Operator Permissions, Governance, and Audit](../store/governance-audit.md); for the trust-domain boundary of identity registration, see [Identity Registry: Real-World Identity and On-Chain Addresses](../trust/domains.md).

```text
Store review material
  -> governance request
  -> Store or external institution/admin action
  -> UVPIdentityRegistry binding event (identity only)
  -> indexer identity projection
```

## Boundaries

- Store review is platform workflow; trust publication is determined by registry events.
- Store tag/search ranking is catalog and operational semantics; fairness judgments rely on nucleus material and Store or external-institution material review.
- Contact/notification success is contact state; fulfillment completion is determined by signal/proof.
- A docking draft is trial-assembly material; formal runtime depends on publication, registration, authorization, and docking events.
- The Store audit trail records platform activity; on-chain proof is displayed separately.

# Store Console, Supplier, and Governance API

The Store APIs serve the Nucleus, Store operators, reviewers, and governance admins. They organize Zhixu drafts, supplier profiles, docking sessions, review material, publication workflow, identity requests, and audit trails. The Nucleus governs its coordination design, the Store API owns platform workflow, and the Identity Registry projection resolves subject/account mappings.

## Store Console

Store Console is aimed at the Nucleus workbench:

- Zhixu search, catalog, and detail.
- draft import, compile preview, submit review, request publication.
- version, runtime, active recommendation, chain publication projection.
- docking sessions, used to try stitching together peer Zhixu, adapters, or signal maps.
- audit trail, used to record platform workflow actions.

These states belong to platform workflow and material organization. Identity binding is expressed by `UVPIdentityRegistry`; capability and matching remain off-chain Store judgments.

## Supplier Directory

The Supplier API organizes materials for real-world fulfillment networks:

- supplier subject, wallet, and display name.
- capability tags, role/stage availability.
- contact profile, owner, SLA, and operational notes.
- participation history, open tasks, proof links.
- review, publication request, revocation request.

Store admins can maintain the platform directory and review materials. Participation rules inside Zhixu are decided by the Nucleus, and order-level authorization is generated by the Product BFF and checked by the contract.

## Governance Workflow

The Governance API manages platform review, identity-binding register/revoke requests, transaction intent, and audit. It organizes materials and initiates Registry actions; `UVPIdentityRegistry` events and projections express the recorded result.

```text
Store review material
  -> governance request
  -> Store or external institution/admin action
  -> UVPIdentityRegistry binding event (identity only)
  -> indexer identity projection
```

## Boundary

- Store review is platform workflow; trust publication is determined by registry events.
- Store tag/search ranking is catalog and operational semantics; fairness judgments rely on nucleation materials and Store or external institution endorsement.
- Contact/notification success is contact state; fulfillment completion is determined by signal/proof.
- Docking drafts are trial-assembly materials; formal runtime depends on release, registration, authorization, and docking events.
- The Store audit trail records platform activity; on-chain proof is shown separately.

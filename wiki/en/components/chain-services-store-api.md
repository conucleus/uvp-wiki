# Store Console, Supplier, and Governance API

The Store-related APIs are the workspace surfaces for the Nucleus, Store operators, reviewers, and governance admins. They organize Zhixu drafts, supplier profiles, docking sessions, review materials, attestation requests, and audit trails. Inside Nucleus governance, the trust registry decides external endorsement, while the Store API handles platform workflow.

## Store Console

Store Console is aimed at the Nucleus workbench:

- Zhixu search, catalog, and detail.
- draft import, compile preview, submit review, request attestation.
- version, runtime, active recommendation, chain attestation projection.
- docking sessions, used to try stitching together peer Zhixu, adapters, or signal maps.
- audit trail, used to record platform workflow actions.

These states belong to platform workflow and material organization. External endorsement is expressed by `ZhixuTrustRegistry` events.

## Supplier Registry

The Supplier API organizes materials for real-world fulfillment networks:

- supplier subject, wallet, and display name.
- capability tags, role/stage availability.
- contact profile, owner, SLA, and operational notes.
- participation history, open tasks, proof links.
- review, attestation request, revocation request.

Store admins can maintain the platform directory and review materials. Participation rules inside Zhixu are decided by the Nucleus, and order-level authorization is generated by the Product BFF and checked by the contract.

## Governance Workflow

The Governance API manages platform review, attestation/revocation requests, tx intent, and audit. It can organize materials and initiate trust-domain actions; fairness/trust facts are expressed by registry events and projections.

```text
Store review material
  -> governance request
  -> trust-domain/admin action
  -> ZhixuTrustRegistry event
  -> indexer trust projection
```

## Boundary

- Store review is platform workflow; trust attestation is determined by registry events.
- Store tag/search ranking is catalog and operational semantics; fairness judgments rely on nucleation materials and trust-domain endorsement.
- Contact/notification success is contact state; fulfillment completion is determined by signal/proof.
- Docking drafts are trial-assembly materials; formal runtime depends on release, registration, authorization, and docking events.
- The Store audit trail records platform activity; on-chain proof is shown separately.
